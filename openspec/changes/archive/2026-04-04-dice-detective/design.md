## Context

Dice Detective is a 5-round counting game. Two custom dice (4 faces each, up to 3 shape types) produce a 4×4 sample space grid of 16 outcomes. Each round a counting question is asked; the player answers by tapping cells (rounds 1–2) or typing a number (rounds 3–5). Dice configs and question types are procedurally generated so every session is different.

The game sits between PizzaBuilder (which shows sample space as a static grid) and LuckyCombo (which teaches AND probability). It teaches: count favorable outcomes before computing probability.

## Goals / Non-Goals

**Goals:**
- 5-round session with procedurally randomised dice configs and questions
- 4×4 grid showing all 16 outcome cells (shape from die A × shape from die B)
- Rounds 1–2: tap-cell mode — player taps matching cells, submits, sees cell-level feedback
- Rounds 3–5: count mode — player types a number, submits, cells highlight with one-line math
- 5 question templates covering all counting scenarios
- Guard: answers must be 1–15 (not trivial, not total)
- Full EN/HE i18n

**Non-Goals:**
- Probability fractions (this game stays at counting; no P = favorable/total displayed)
- More than 3 shape types or more than 4 faces per die
- Player-editable dice (configurations are randomised, not user-defined)

## Decisions

### Dice data model

```js
// A die is an array of face values (shapes)
// e.g. ['triangle','triangle','square','circle']
// Each face has equal weight (uniform die)

// Shape palette
const SHAPES = ['triangle', 'square', 'circle']

// Die face counts: 4 faces, at least 2 distinct shapes
// generated by: pick 2-3 shapes, distribute 4 faces among them
// examples:
//   [2,2]   → ['triangle','triangle','square','square']
//   [2,1,1] → ['triangle','triangle','square','circle']
//   [3,1]   → ['triangle','triangle','triangle','square']
```

A die is represented as `string[]` of length 4. The sample space is the cartesian product: `dieA × dieB` → 16 `[shapeA, shapeB]` pairs.

### Question templates

```
Template          Description                         Formula
─────────────────────────────────────────────────────────────────
ONE_DIE           "[shape] on the [color] die?"       cA(s) × 4   (or 4 × cB(s))
BOTH_SAME         "[shape] on BOTH dice?"             cA(s) × cB(s)
AT_LEAST_ONE      "At least one [shape]?"             16 - (4-cA(s)) × (4-cB(s))
EXACTLY_ONE       "[shape] on exactly ONE die?"       cA(s)×(4-cB(s)) + (4-cA(s))×cB(s)
DIFFERENT_SHAPES  "Different shapes on each die?"     16 - Σ_s cA(s)×cB(s)
```

Template assigned by round: R1→ONE_DIE, R2→BOTH_SAME, R3→ONE_DIE, R4→AT_LEAST_ONE, R5→EXACTLY_ONE or DIFFERENT_SHAPES (pick whichever has a non-trivial answer).

### Procedural generation

```js
function generateRound(roundIndex) {
  const template = TEMPLATES[roundIndex]
  let attempt = 0
  while (attempt++ < 100) {
    const dieA = randomDie()   // 4 faces, 2-3 distinct shapes
    const dieB = randomDie()
    const shape = pickShape(dieA, dieB, template) // shape referenced in question
    const answer = computeAnswer(template, shape, dieA, dieB)
    if (answer >= 1 && answer <= 15) {
      return { dieA, dieB, template, shape, answer }
    }
  }
  // fallback: guaranteed-valid config (hardcoded)
}
```

`randomDie()`: pick random distribution from `[[2,2],[2,1,1],[3,1]]`, shuffle shapes into faces.

### Grid rendering

The grid is always fully visible. Columns = die B faces, rows = die A faces.

```
           dieB[0]  dieB[1]  dieB[2]  dieB[3]
dieA[0]    [A0│B0]  [A0│B1]  [A0│B2]  [A0│B3]
dieA[1]    [A1│B0]  [A1│B1]  [A1│B2]  [A1│B3]
dieA[2]    [A2│B0]  [A2│B1]  [A2│B2]  [A2│B3]
dieA[3]    [A3│B0]  [A3│B1]  [A3│B2]  [A3│B3]
```

Each cell shows two shape SVGs (die A shape on top, die B shape below), small and clear.
Cells are square, ~64px on mobile. Grid has a header row (die B faces) and header column (die A faces) coloured by die colour.

Shape SVGs — inline, no library:
- triangle: `<polygon points="12,2 22,22 2,22"/>`
- square: `<rect x="3" y="3" width="18" height="18"/>`
- circle: `<circle cx="12" cy="12" r="9"/>`

Die colours: die A = rose-500 (`#F43F5E`), die B = blue-500 (`#3B82F6`).

### Tap mode (rounds 1–2)

```
state: selected = Set of cell indices (0–15)

Cell tap → toggle selected
Submit tap:
  correctSet = indices where cell matches condition
  for each cell:
    if in selected ∩ correctSet → green
    if in selected but NOT correctSet → red (wrong tap)
    if NOT selected but in correctSet → amber (missed)
  show: "X out of Y — [explanation line]"
  Next button appears
```

No score, no points — feedback only. Learning is the goal.

### Count mode (rounds 3–5)

```
state: typed = string (numeric input)

Player types number → submit
  correct = typed === answer
  highlight correctSet cells in green
  show one-line explanation
  if wrong: shake input, show correct answer, highlight cells anyway
  Next button appears
```

One attempt only — reveal immediately on submit (no retry). Seeing the correct cells after a wrong answer is the learning moment.

### One-line math explanations

```
ONE_DIE:         "Die [color] shows [shape] on [cA] of its 4 faces × 4 outcomes = [answer]"
BOTH_SAME:       "[cA] × [cB] — multiply the counts on each die"
AT_LEAST_ONE:    "16 total − [4-cA] × [4-cB] (outcomes with no [shape]) = [answer]"
EXACTLY_ONE:     "[cA] × [4-cB] (only on red) + [4-cA] × [cB] (only on blue) = [answer]"
DIFFERENT_SHAPES:"16 total − [same-shape outcomes] = [answer]"
```

### Round flow

```
phase: 'intro' → 'active' → 'revealed' → 'next'

intro:   Show dice visuals, animate faces appearing (stagger, 200ms each)
         Show question
active:  Tap cells (tap mode) or type number (count mode)
         Submit button enabled once ≥1 tap or any digit typed
revealed: Show feedback (cell colours / typed result)
          Show explanation line
          "Next" button (or "See Results" on round 5)
next:    Transition to next round (fade out grid, fade in new)
```

### End screen

After round 5:
- Count of rounds with a correct first answer
- "5/5 — Sharp eye! 🔍" / "3/5 — Good start!" / "1/5 — Keep practising"
- "Play again" shuffles all 5 rounds fresh

## Risks / Trade-offs

- **Procedural generation loops** — `while(answer < 1 || answer > 15)` could spin on degenerate configs. Mitigated by 100-attempt cap + guaranteed fallback config per template.
- **DIFFERENT_SHAPES on uniform dice** — if both dice have identical shape distributions, DIFFERENT_SHAPES answer is predictable. Mitigated by assigning it only to round 5 and preferring EXACTLY_ONE if configs match.
- **Mobile grid density** — 4×4 at ~64px/cell = 256px plus headers. Fits 320px+ screens. Smallest supported target is 360px wide (Android minimum in this app).
- **Hebrew shape names in explanation strings** — interpolated strings with RTL text and numbers. Use `dir="ltr"` on the number span inside RTL explanation lines.
